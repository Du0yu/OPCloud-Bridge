# OPCloud Bridge

[简体中文](./README.md) | [English](./README.en.md)

OPCloud Bridge adds local model import/export to [OPCloud Sandbox](https://opcloud-sandbox.web.app/) and lets Agents such as Codex and Claude operate the model open in your browser through MCP.

After installation, a **Model Import / Export** panel appears in the bottom-right corner of OPCloud. Model files are processed locally in your browser and are not uploaded to another server.

## One-click installation

Install [Tampermonkey](https://www.tampermonkey.net/) or [Violentmonkey](https://violentmonkey.github.io/), then click:

### [➡️ Install OPCloud Bridge](https://raw.githubusercontent.com/Du0yu/OPCloud-Bridge/main/opcloud-model-io.user.js)

Your userscript manager will open its installation confirmation page. The script includes update URLs, so newer releases can be detected automatically.

## Features

![OPCloud Bridge connected to OPCloud and an MCP Agent](assets/demo.png)

- Export the complete current model as an `.opcl` file
- Import `.opcl` and compatible `.json` files
- Export the current OPD as a 2× resolution JPEG
- Export the current OPD as scalable SVG
- Save the OPL generated for the current model as a local UTF-8 text file
- Rebuild the OPD, navigation tree, and OPL after import
- Ask for confirmation before replacing a non-empty model
- Adapt automatically when OPCloud Webpack module IDs change
- Include a ready-to-import two-dish dinner example
- Provide a local MCP server for reading, importing, validating, reviewing OPL, and exporting images
- Connect the userscript to the local MCP bridge without modifying the OPCloud website
- Display the plugin interface in English or Chinese, selected automatically from the browser language or manually from the panel

## Agent / MCP mode

The connection architecture is:

```text
Codex / Claude / MCP Client
          ↕ MCP stdio
Local OPCloud Bridge process
          ↕ WebSocket (127.0.0.1:17373)
Userscript ↔ OPCloud page
```

A userscript cannot listen on a browser port, so the local process acts as both an MCP server and a WebSocket server. The userscript connects to it and retries automatically after a disconnect.

### MCP client configuration

After installing the userscript, an MCP client can launch the bridge directly from GitHub:

```json
{
  "mcpServers": {
    "opcloud": {
      "command": "npx",
      "args": ["-y", "github:Du0yu/OPCloud-Bridge"]
    }
  }
}
```

Some Windows clients require `npx.cmd` instead of `npx`. Restart the MCP client after configuration, then open or refresh [OPCloud Sandbox](https://opcloud-sandbox.web.app/). The connection is ready when the bottom-right panel shows **MCP: Agent connected**.

You can also clone and run the repository locally:

```bash
npm install
npm start
```

For a local checkout, configure the MCP command as `node` and pass the absolute path to `mcp-server/server.js`. With Codex CLI:

```powershell
codex mcp add opcloud -- node "C:\path\to\OPCloud-Bridge\mcp-server\server.js"
codex mcp get opcloud
```

Replace `C:\path\to\OPCloud-Bridge` with the absolute path of your clone. Start a new Codex session after registration. Codex launches the MCP server automatically, so you do not need to run `npm start` at the same time.

### Connection test

Call these tools in a new Agent session:

1. `opcloud_status` should return `connected: true` and `opcloud.ready: true`.
2. `opcloud_get_model` should return the current model, OPDs, and logical elements.
3. `opcloud_get_opl` should return the OPL generated from the current model.
4. `opcloud_review_diagram` should return a model summary, OPL, and the actual canvas image with MIME type `image/jpeg`.

The project has been tested end to end with a blank OPCloud model: the userscript connected to the local WebSocket, and the Agent read `Model (Not Saved)`, empty OPL, and a white JPEG matching the empty canvas.

### MCP tools

| Tool | Purpose |
|---|---|
| `opcloud_status` | Check whether the userscript, page, and model are ready |
| `opcloud_get_model` | Read the complete current model JSON |
| `opcloud_import_model` | Load a complete JSON/OPCL model into the current page |
| `opcloud_get_opl` | Read the OPL sentences generated by OPCloud |
| `opcloud_validate_model` | Validate JSON, IDs, OPDs, state parents, and link references |
| `opcloud_export_image` | Return the current OPD as JPEG or SVG |
| `opcloud_review_diagram` | Return a model summary, OPL, and the current OPD JPEG for visual Agent review |

When the current canvas is non-empty, `opcloud_import_model` requires `replaceExisting: true` to prevent accidental replacement.

The recommended Agent loop is:

```text
Read current model → generate or edit → validate → import → read OPL + exported image → correct → import and review again
```

`opcloud_review_diagram` returns an image generated from the live OPCloud canvas through its native `toJPEG()` method, not an approximate redraw of the JSON. MCP clients with image input can pass the JPEG directly to the Agent so it can inspect overlaps, clipped text, state placement, crossing links, and missing elements.

## Installation

### Method 1: install from Git hosting

1. Install [Tampermonkey](https://www.tampermonkey.net/) or [Violentmonkey](https://violentmonkey.github.io/) in your browser.
2. Open the [one-click install link](https://raw.githubusercontent.com/Du0yu/OPCloud-Bridge/main/opcloud-model-io.user.js).
3. Choose **Install** on the userscript manager page.
4. Open or refresh [OPCloud Sandbox](https://opcloud-sandbox.web.app/).

### Method 2: local installation

1. Open your userscript manager and choose **Add new script**.
2. Paste the full contents of [`opcloud-model-io.user.js`](./opcloud-model-io.user.js).
3. Save the script and refresh OPCloud.

## Usage

### Change the interface language

On first run, the plugin selects English or Chinese from the browser's preferred languages. Click `中文` or `EN` in the panel header to switch manually. The selection is saved in browser local storage for the OPCloud site.

### Export a model

1. Create or modify a model in OPCloud.
2. Click **Export model** in the bottom-right panel.
3. The browser downloads a formatted `.opcl` file.

### Import a model

1. Click **Import model**.
2. Select an `.opcl` or compatible `.json` file.
3. Confirm replacement if the current canvas contains a model.

### Export an image

- Click **Export JPEG** to download a 2× resolution bitmap of the current OPD.
- Click **Export SVG** to download a vector image of the current OPD. Prefer SVG when the diagram contains background images.

### Save OPL

Click **Save OPL** to read the OPL generated by OPCloud for the current model and download it as a UTF-8 `.opl.txt` file. Its filename includes the model name and current OPD name.

You can test importing with [`examples/Two-Dish-Dinner-Corrected.opcl`](./examples/Two-Dish-Dinner-Corrected.opcl).

## Local validation

Install dependencies with Node.js 20 or later and run:

```bash
npm install
npm test
```

This checks the userscript and MCP server syntax and validates the example OPCL JSON, IDs, OPDs, state parents, and link references.

## How it works

The script reuses OPCloud's own model APIs:

- Export calls the model's `toJson()` method.
- Import calls the model's `fromJson()` method.
- After import, it invokes OPCloud's native tree navigation and graph rendering flow.
- The MCP server communicates with the Agent through standard input/output and forwards tool calls to the userscript over a localhost WebSocket.

These are internal site APIs. A substantial future OPCloud frontend change may require a corresponding script update.

## Instructions for Agents

Before using a coding Agent to generate or modify JSON/`.opcl`, ask it to read [`AGENTS.md`](./AGENTS.md). That document requires complete, directly importable files and defines OPCloud JSON reference rules, OPM link enums, state transitions, expected OPL forms, and pre-delivery validation.

## Privacy

- The project contains no analytics or telemetry.
- Normal import/export mode sends no network requests.
- MCP mode connects only to `127.0.0.1:17373`; it does not upload models to a remote server.
- The local WebSocket accepts browser connections only from `https://opcloud-sandbox.web.app`.
- The MCP service listens only on the loopback interface, not on your LAN or the public internet.
